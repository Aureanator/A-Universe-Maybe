**2. Findings open in this round.**
- **F1 (two-referee; Astra R2 and Opus R3, independently).** The μ justification is false as written. Twelve boundary-vertex transforms (constant λᵢ = μ) fix an identity-labelled B pointwise, and within a single fixed fibre the count runs raw 72 → apex-only 6 → full pointwise stabilizer (144) 2. The collapse happens *inside* the fibre, so the docstring's "never within a fixed fibre" is exactly backwards. The rigid count remains defensible — but only as an explicit apparatus convention in which boundary frames are physical data and boundary gauge transforms are forbidden by fiat. If that is the intent, the module should say so; if not, pooled is the physical default. The number is fine; the sentence is the defect, and it currently ships in three places.
- **F2 (Opus R3).** The `resolutions.py` convention warning quotes "rigid 6 → pooled 1, rigid 12 → pooled 2." The true pairs across all 103 declarations are 6→2 (7 declarations) and 12→1 (36) — transposed. `CRITIQUE_TRIAGE.md` is correct; the docstring a code reader hits first is not. Small, but it lives inside the warning whose entire function is to prevent misquotation.
- **F3 (Astra R2, carried; single-referee confidence).** Shadow-fix wiring: `DriverA.advance()` still proposes from the non-closed generator set and accepts on `appearance()`; a seed-0 tetrahedron update preserves `appearance()` while changing the canonical state, so the default path accepts moves its own new machinery classifies as distinguishable. The corrected model exists but is not load-bearing. Suggestion: wire it in, or fork experiments per model and add a model-provenance column to every stochastic row.

Either loop over components or raise on unsupported regions; the completeness claim needs its domain stated.

**3. Cross-cutting observation.** The arc's residual failure mode is no longer code; it is justification drift. The count was corrected while the sentence explaining it stayed wrong, and the wrong sentence shipped three times as a rebuttal. Numbers get tested; prose doesn't. In the spirit of the project's own pre-registration discipline, the panel offers one process suggestion: extend pre-registration to justifications. When a probe confirms a count, commit the one-line mechanism claim beside it, pinned by an executable check — here the stabilizer enumeration itself (12 pointwise-fixing transforms; 72→6→2) is precisely such a check, and would let the sentence fail CI the way a number can. A claims register (measured / derived / postulated / scheduler-artifact, plus producing model) would generalize the "mark theorems as theorems" rule the repo already honours.
